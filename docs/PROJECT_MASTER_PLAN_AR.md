# الخطة الشاملة لمشروع CrossPlatformDataTransfer

تاريخ الخطة: 2026-11-22. الفرع الذي يحتوي خط الأساس الحالي: `codex/recovery-audit-completion`، والالتزام المنشور `23419cf`.

## 1. ما المنتج المقصود؟

أداة Windows بواجهة واضحة على نمط أدوات إدارة الهاتف، تساعد مالك الهاتف على اكتشاف جهازه، ثم اختيار أنواع محددة من البيانات ونقلها أو نسخها احتياطيًا واستعادتها عبر واجهات النظام الرسمية. المطلوب منتج موثوق وقابل للتوزيع التجاري، مع شرح الأذونات والقيود، وليس ادعاء نسخ كل شيء من كل هاتف. قدرات Android وiOS تختلف، وبعض البيانات لا تسمح المنصة بالوصول إليها لتطبيق طرف ثالث.

## 2. الحالة الحقيقية الآن

- مستودع GitHub يحتوي الآن فرع المراجعة `codex/recovery-audit-completion`، ولم يُدمج في `main`.
- واجهة Windows WPF التجريبية تفتح، وتكتشف جهاز Samsung SM-A135F A13 عبر ADB. توجد معاينة محلية للواجهة، لكنها ليست حزمة إصدار موقعة.
- تطبيق Android Kotlin الأولي بُني وثُبّت على هاتف المالك A13 فقط. النسخة الحالية تحوي محاولة TLS؛ لم تنجح المصافحة الميدانية الأخيرة لأن خدمة الوكيل على الهاتف كانت متوقفة.
- الأوامر المتاحة في الوكيل هي الاقتران/الفحص/المصافحة/القدرات. لا توجد أوامر ملفات أو صور أو جهات اتصال أو رسائل، ولا نقل بيانات شخصي.
- خادم TCP القديم غير المشفر ومسارات ADB الخطرة التي تنفذ shell/root/نسخ ملفات أزيلت أو عُطلت. لا يستخدم المشروع root.
- بناء .NET اجتاز دون أخطاء أو تحذيرات في التحقق السابق، واجتازت اختبارات حدود الأمان الستة. بناء Android نجح دون اتصال في التحقق الأخير.
- النتيجة: هذا نموذج أولي للاتصال والواجهة، وليس بعد برنامج نقل شاملًا أو جاهزًا للبيع.

## 3. ضوابط إدارة العمل

1. ننفذ **مرحلة واحدة فقط** في كل دورة. لا يبدأ العمل في التالية قبل تقرير قبول مكتوب ومراجعة المستخدم.
2. لكل مرحلة: نطاق محدد، ملفات متوقعة، مخاطر، تحقق قابل للتكرار، ومخرجات إثبات.
3. يحلل Claude التغيير قراءةً أولًا ويكتب ملاحظات مرتبطة بالملف والسطر. ينفذ Codex بعد ذلك التعديل المتفق عليه. ثم يراجع Claude الفرق الجديد. لا يكتب الوكيلان الملف نفسه بالتوازي.
4. لا حذف أو تغيير بيانات الهاتف، ولا تثبيت على أي هاتف غير A13، ولا صلاحية root. الاختبارات على هاتف المستخدم فقط وبموافقته لكل عملية بيانات شخصية.
5. لا رفع إلى `main` ولا إصدار ولا نشر متجر قبل مراجعة المستخدم. ترفع المراحل إلى فروع أو commits صغيرة مع أسماء واضحة.
6. الادعاء «مكتمل» يتطلب الدليل الخاص به: بناء، اختبارات، تحقق يدوي على المنصة المعنية، تحديث مصفوفة القدرات، مراجعة أمنية وتوثيق.
