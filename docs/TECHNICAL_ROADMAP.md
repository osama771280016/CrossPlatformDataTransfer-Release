# خارطة الطريق التقنية

الأولوية لسلامة بيانات المستخدم والصدق في حالة العملية. لا تُعلن أي ميزة مكتملة قبل تنفيذها والتحقق منها على المنصات المعنية.

## الحالة الحالية — 2026-11-22

- تطبيق Windows WPF يفتح ويكتشف هاتف Samsung SM-A135F عبر ADB.
- أُعيد تصميم لوحة Windows بالعربية وبنمط إدارة أجهزة أوضح، مع فحص ADB تلقائي عند الفتح وحالة واضحة عند غياب الهاتف. حزمة المعاينة الحالية في `outputs/CrossPlatformDataTransfer-Windows-Dashboard-Preview`.
- بعد إعادة توصيل الكابل ظهر A13 مجددًا في واجهة Windows. خدمة Android Agent ما زالت متوقفة، لذلك لم تبدأ جلسة TLS.
- إصدار Android Agent السابق اجتاز الاقتران والمصافحة على Android API 34. تحديث TLS الحالي بُني وثُبّت، لكن لم تثبت مصافحته بعد.
- اتصال الإصدار الحالي يسمح بالمصافحة وقراءة معلومات عامة فقط؛ لا يقرأ ولا ينقل ملفات أو صورًا أو جهات اتصال أو رسائل.
- نُشرت نسخة TLS على A13 ونجح تثبيتها وفتح واجهة Android. لم تكتمل بعد مقارنة بصمة الشهادة وموافقة المستخدم والاقتران في هذه النسخة.
- بناء الحل .NET نجح دون تحذيرات أو أخطاء، واجتازت اختبارات حدود الأمان الستة.
- أُزيل خادم TCP القديم غير المشفر وواجهات ADB التي تنفذ shell أو root أو نسخًا مباشرًا للملفات. اختير Android SDK ADB بدل نسخة قديمة موجودة في `C:\Windows`.
- لا تُوزع نسخة Debug كإصدار نهائي. مفاتيح التوقيع والتحديثات الرسمية غير معدة.

## خطة الإنجاز

### المرحلة 0 — خط الأساس والتدقيق (مكتملة جزئيًا)

- تدقيق السلوك الأصلي وإزالة ادعاءات النجاح الوهمية ومسارات SMS التي تعتمد على root.
- تسجيل حقيقة أن اتصال الهاتف يعمل وأن النقل غير موجود بعد.
- إبقاء التغييرات محلية إلى حين طلب المستخدم دفعها إلى مستودع بعيد.

### المرحلة 1 — نموذج الأمان وبروتوكول الجلسة (قيد التنفيذ)

- توثيق نموذج الثقة والبيانات التي يسمح بعبورها وحدود ADB.
- استخدام TLS القياسي عبر Android `SSLServerSocket` و.NET `SslStream`، مع شهادة EC مؤقتة في Android Keystore ورمز مقارنة ظاهر في الهاتف وWindows.
- عدم إرسال PIN أو بيانات قبل تأكيد المستخدم تطابق رمز الشهادة على الطرفين؛ TLS يتولى تشفير الإطارات ومصادقتها.
- رفض الأوامر القديمة أو غير الموثقة؛ لا تُرسل بيانات ملفات قبل اكتمال حماية الجلسة.
- أُنجز نموذج الأمان ونُفذ TLS على الطرفين. التثبيت الحالي على A13، واجهة Windows المعاينة مفتوحة. الاختبار ينتظر مقارنة البصمة وموافقة المستخدم ثم التحقق من الاقتران على الجهاز.
- محاولة TLS السابقة فشلت لأن خدمة Android Agent كانت متوقفة. ظهر A13 مجددًا بعد إعادة توصيل USB، لكن الخدمة وتمريرة 4711 غير نشطتين؛ لا توجد جلسة آمنة ناجحة مثبتة حتى الآن.
- القبول: Android وWindows يتفقان على مفتاح الجلسة، ويرفضان تعديل الإطار أو تكراره أو عميلًا غير مؤكد.

### المرحلة 2 — أول نقل ملف اختياري من Android إلى Windows

- اختيار ملف واحد من واجهة Android الرسمية Storage Access Framework؛ لا `MANAGE_EXTERNAL_STORAGE` ولا root.
- عرض الاسم والحجم والنوع قبل النقل، وطلب بدء النقل صراحة من Windows.
- نقل مجزأ ومحدود الحجم فوق جلسة مشفرة، مع تقدم حقيقي وإلغاء ومهلة.
- حفظ عبر نافذة Windows يختارها المستخدم إلى ملف مؤقت، ثم التحقق من الحجم وSHA-256 قبل اعتماد الملف.
- منع اجتياز المسارات والكتابة فوق ملف موجود بلا اختيار صريح.
- القبول: ملف يختاره المستخدم يصل byte-for-byte، وتُرفض نتيجة الملف غير المكتمل أو المعدل.

### المرحلة 3 — نقل ملف من Windows إلى Android

- اختيار الملف على Windows، ثم اختيار مجلد/وجهة Android بواجهة Storage Access Framework.
- طلب تأكيد واضح على الهاتف قبل إنشاء الملف.
- استخدام اسم آمن وفحص الحجم وSHA-256 قبل إغلاق الملف النهائي.
- القبول: الملف يطابق المصدر، والإلغاء/انقطاع الاتصال لا يترك ملفًا نهائيًا فاسدًا.

### المرحلة 4 — النسخ الاحتياطي والاستعادة

- إنشاء manifest بإصدار وصنف واسم وحجم ووقت وSHA-256 لكل ملف اختير يدويًا.
- فحص مساحة التخزين قبل البدء، وتقرير مستقل لكل عنصر.
- استعادة إلى وجهة يختارها المستخدم، مع معاينة التعارضات ومنع الكتابة غير المقصودة.
- لا استئناف ولا مزامنة حذف قبل توثيق نقاط الحفظ والتحقق منها.

### المرحلة 5 — وحدات Android الرسمية

- الملفات والصور والفيديو عبر Storage Access Framework أو Android Photo Picker حسب نوع المحتوى.
- جهات الاتصال وسجلات المكالمات وSMS كوحدات منفصلة، بإذن Android الرسمي وتوضيح أثره قبل طلبه.
- لا root ولا قراءة قواعد بيانات خاصة أو تجاوز قيود Android. تُسجل حدود كل إصدار بوضوح.

### المرحلة 6 — iOS والتوزيع

- بحث مستقل عن واجهات Apple الرسمية لكل فئة بيانات؛ لا نفترض إمكانية نقل بيانات التطبيقات أو الرسائل.
- مصفوفة توافق واختبار على أجهزة حقيقية بحسب المتاح.
- حزمة Windows موقعة فقط عند توافر شهادة حقيقية؛ لا توقيع صوري.
- إصدار Android Release موقّع بمفتاح يملكه المستخدم، مع تعليمات حفظ المفتاح وعدم تضمينه في المستودع.

## قواعد القبول العامة

- كل مرحلة توضح ما تستطيع فعله وما لا تستطيع فعله، وتقدم فشلًا صريحًا عند انقطاع النقل.
- لا أذونات واسعة ولا إرسال إلى خادم خارجي ولا تخزين مفاتيح/رموز اقتران في السجلات.
- لا يُعلن نجاح النقل حتى اكتمال الملف وفحص سلامته.
- تُبنى التطبيقات وتُتحقق نتائجها قبل الانتقال. تُجرى اختبارات التكامل على الهاتف عندما تتطلب المرحلة ذلك.
