# بروتوكول وكيل Android — الإصدار الأول (اقتران فقط)

## النطاق

هذا البروتوكول يهدف إلى اتصال واقتران عبر USB/ADB فقط. النسخة الأولى غير المشفرة اجتازت اختبارًا أوليًا على هاتف Samsung SM-A135F بنظام Android API 34. بُني تحديث TLS وثُبّت على الهاتف، لكن أحدث محاولة لم تكتمل لأن خدمة Android foreground agent كانت متوقفة؛ لذلك لا نعد TLS متحققًا ميدانيًا حتى يجتاز اختبار القبول. لا يتيح البروتوكول قراءة ملفات أو جهات اتصال أو رسائل ولا يكتب بيانات إلى الهاتف. متطلبات حماية القناة موثقة في [نموذج الأمان](SECURITY_MODEL.md).

## النقل

- المنفذ المحلي على الهاتف: `4711`.
- يستمع الوكيل على `127.0.0.1` فقط.
- ينشئ الكمبيوتر تحويلًا محددًا: `adb -s <serial> forward tcp:4711 tcp:4711`.
- يبدأ النقل بمصافحة TLS (TLS 1.2 على الأقل) باستخدام شهادة EC مؤقتة يولدها Android Keystore لكل تشغيل للوكيل. يحذف الوكيل مفتاح الشهادة عند انتهاء الجلسة.
- يجب أن يعرض Windows والهاتف رمز SHA-256 المتطابق من الشهادة. يؤكد المستخدم الرمز في الهاتف ثم في Windows قبل إرسال رمز الاقتران أو أي أمر تطبيق.
- داخل TLS، كل رسالة تطبيق: عدد صحيح 32 بت بترتيب Big Endian يمثل طول JSON UTF-8، يتبعه JSON.
- الطول المقبول من 1 إلى 1,048,576 بايت. يغلق الطرف الاتصال عند الطول الخارج عن الحد.

## الطلب والاستجابة

طلب:

```json
{"commandType":"PAIR","parameters":{"pairingCode":"12345678"}}
```

استجابة:

```json
{"success":true,"message":"تم اقتران هذه الجلسة مؤقتًا","data":null}
```

بعد مصافحة TLS وموافقة المستخدم على رمز الشهادة، يجب أن يكون `PAIR` أول أمر تطبيق. رمز الاقتران عشوائي مؤقت من 8 أرقام، ويُقارن مقارنة ثابتة الزمن، ويُغلق الاتصال بعد خمس محاولات خاطئة. لا يحفظه الوكيل على القرص.

## الأوامر المسموحة بعد الاقتران

| الأمر | السلوك |
|---|---|
| `PING` | يعيد `PONG` |
| `HANDSHAKE` | يعيد إصدار البروتوكول وطراز الجهاز ومستوى Android |
| `GET_CAPABILITIES` | يعيد قائمتي قراءة وكتابة فارغتين في الإصدار الأول |

كل الأوامر الأخرى تُرفض. لا تُرسل بيانات حساسة أو أسرار في سجلات التشغيل.

## ملاحظات التوافق

- عميل .NET يكتب الطول بـBig Endian. يجب أن يقرأ Kotlin ويكتب الترتيب نفسه.
- `AndroidAgentClient` يفتح اتصالًا بعد إعداد `adb forward`؛ يجب أن تكون خدمة الهاتف بدأت يدويًا قبل الاتصال.
- لا يتوافق `TcpAgentServer` القديم مع اتجاه الاتصال هذا أو مع غلاف JSON نفسه، فلا يُستخدم مع الوكيل في هذا الإصدار.
- لا تُفعّل `SendEncryptedPayloadAsync` أو تدفق الأجزاء مع الوكيل الحالي؛ نقل الملفات يحتاج عقدًا منفصلًا مع ACK وهاشات واختبارات بين الطرفين.

## حالة التنفيذ

| الميزة | الحالة |
|---|---|
| USB/ADB وتفويض الكمبيوتر | متحقق على هاتف واحد |
| رمز اقتران ومصافحة التطبيق | متحقق على هاتف واحد في الإصدار الأول |
| TLS وAndroid Keystore ورمز تحقق متبادل | كُتب وبُني وثُبّت على A13؛ فشل الاختبار الأخير لأن خدمة الوكيل لم تكن عاملة، ويلزم تكرار الاختبار |
| اختيار ملف عبر Storage Access Framework | غير منفذ |
| نقل ملفات مجزأ والتحقق من السلامة | غير منفذ |

لا يُرقّى الإصدار إلى بروتوكول ملفات حتى يُختبر TLS على الهاتف ويُتحقق من اختلاف الشهادة، والموافقة على الطرفين، وفشل الاتصال بوضوح.
