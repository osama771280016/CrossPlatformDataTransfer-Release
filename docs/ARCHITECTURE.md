# معمارية النظام

## المعمارية الموجودة

الحل يستهدف .NET 8 ويضم:

- **Core:** كيانات الأجهزة والجلسات والملفات وعقود الخدمات والمستودعات.
- **Application:** حالات استخدام الاكتشاف والنقل وDTOs ومحرك نقل الأجزاء.
- **Infrastructure:** اكتشاف ADB وتمرير منفذ محدد وعميل Android Agent عبر `SslStream`؛ لا يُستخدم خادم TCP القديم غير المشفر.
- **Infrastructure.Security:** AES-GCM وECDH وإدارة مفاتيح وهاش واقتران وترخيص.
- **Startup:** تجميع تسجيل الاعتماديات.
- **UI:** WPF/MVVM.
- **CLI:** وضع خادم TCP القديم معطل؛ التطبيق يوضح ذلك ولا ينشئ مستمعًا شبكيًا.
- **Android Agent:** بُني تطبيق Kotlin تجريبي وثُبّت على A13. إصدار الاقتران الأول نجح؛ تحديث TLS بُني وثُبّت، لكن آخر محاولة لم تكمل لأن خدمة الهاتف كانت متوقفة، لذلك TLS غير متحقق ميدانيًا.

الاتجاه المقصود للتبعيات هو اعتماد الطبقات الخارجية على عقود Core وبقاء تنسيق الاستخدام في Application. أضيف بدء WPF عبر Bootstrapper وحقن DataContext. ما زال مستودع الأجهزة في الذاكرة تجريبيًا، وحالة استخدام نقل الملف ترفض التنفيذ حتى يتوفر Android Agent موثوق.

## مسار الاكتشاف الحالي ومشكلاته

```text
WPF command → DeviceDiscoveryUseCase → IDeviceDiscoveryService
                                  └── AdbDeviceDiscoveryService → IAdbService → adb process
```

يصدر الاكتشاف أحداثًا إلى ViewModel، ويحافظ على معرف الجهاز حسب serial خلال جلسة التطبيق، لكن لا يحفظ الجهاز بعد في المستودع الدائم. تحديث عناصر WPF يمر عبر Dispatcher لأن المسح يعمل في الخلفية. لم يُختبر حدث الفصل على هاتف فعلي.

## مسار النقل المستهدف

```text
WPF UI → Application use case → transfer coordinator
                              ├── device/content capability provider
                              ├── safe local backup store + manifest
                              └── authenticated transport → Android Agent
                                    ├── permission request at point of use
                                    ├── chunk/ACK/retry/cancel protocol
                                    └── Android data module
```

تعرض الواجهة حالة العملية وتتلقى موافقة المستخدم. ينسق Application العملية والإلغاء والنتيجة. تختص Infrastructure بالوصول إلى ADB والتخزين والنقل. تعالج Security اقتران الأطراف ومفاتيح الجلسات والتشفير والتحقق. لا تسجل الطبقات محتوى SMS أو المفاتيح أو الحمولات.

## حدود الثقة والبروتوكول

- ADB قناة إدارة/نقل بعد موافقة الجهاز؛ اتصال ADB لا يعني أن كل بيانات الهاتف قابلة للقراءة.
- TCP المحلي أو ADB forwarding لا يثبت هوية الطرف. يجب ربط الجلسة بجهاز مقترن ومصادقة الرسائل.
- صيغة الإطار تحدد إصدار البروتوكول وأطوالًا قصوى ورسائل بدء/جزء/ACK/إنهاء/خطأ، ومعرف جلسة ورقم جزء وهاش وحالة استئناف موثقة.
- AEAD يتطلب مفتاح جلسة متفقًا عليه ومصادقًا وnonce فريدًا لكل رسالة بالمفتاح نفسه. لا يكفي توليد مفتاح عشوائي لكل chunk ثم التخلص منه.
- قبل كتابة ملف، تتحقق الوجهة من المسار والاسم والحجم والمساحة وسياسة التعارض. تكتب البيانات مرحليًا ثم تتحقق الهاشات قبل اعتمادها.

### بروتوكول Android Agent الأولي

- الوكيل يستمع محليًا فقط على `127.0.0.1:4711`، ويصل إليه Windows عبر `adb -s <serial> forward` باستخدام جهاز اختاره المستخدم.
- طول JSON UTF-8 يسبق الرسالة كعدد 32 بت Big Endian، والحد الأقصى 1 MiB.
- مصدر الوكيل الحالي ينشئ جلسة TLS مؤقتة، وتتم مقارنة بصمة الشهادة يدويًا قبل `PAIR`. محاولة TLS الأخيرة على A13 لم تصل إلى المصافحة لأن خدمة Android Agent كانت متوقفة؛ لذا يبقى التنفيذ غير متحقق ميدانيًا.
- بعد الاقتران، الأوامر الوحيدة المطبقة هي `PING` و`HANDSHAKE` و`GET_CAPABILITIES`.
- لا توجد أوامر قراءة أو كتابة بيانات في هذه المرحلة. رمز الاقتران لا يغني عن تحقق TLS ولا يفتح النقل وحده.
- خادم `TcpAgentServer` القديم لا يطابق اتجاه الاتصال أو صيغة الرسائل هذه، ولا يُستخدم مع الوكيل الحالي.

## شكل النسخة الاحتياطية المقترح

مجلد مستقل لكل نسخة يحوي `manifest.json` وملفات المحتوى في مسارات مولدة لا تعتمد مباشرة على أسماء الهاتف. يتضمن manifest إصدار الصيغة ومعرف النسخة ومعلومات مصدر مسموح بها ونوع المحتوى والحجم ووقت النسخ والهاش وحالة كل عنصر وتوافق الاستعادة. تفصل بيانات التعريف الحساسة عن السجلات التشغيلية.

## خيارات معمارية معلقة

- تبدأ مرحلة الوكيل الحالية باختبار الاقتران والمصافحة؛ تليها ملفات يختارها المستخدم عبر واجهة Android الرسمية، ثم أنواع البيانات التي تتطلب APIs وأذونات إضافية.
- تصمم وحدات البيانات بحسب قدرات المنصة بدل واجهة توحي بتكافؤ Android وiOS.
- مكان التخزين الافتراضي ومدة الاحتفاظ والتشفير عند السكون تحتاج إعدادات واضحة قبل إصدار عام.
