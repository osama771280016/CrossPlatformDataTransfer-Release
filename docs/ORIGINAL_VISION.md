# الرؤية الأصلية للمشروع

هذه الوثيقة تستند إلى الرؤية التي قدمها مالك المشروع في 2026-11-21، وتفصلها عن الحالة التي يثبتها المستودع. الرؤية هدف تطوير وليست دليلًا على وجود الميزات.

## الغرض

بناء مركز إدارة على Windows لنقل بيانات الهواتف وإنشاء نسخ احتياطية منظمة واستعادتها، مع دعم واسع لأجهزة Android وإمكانية إضافة iPhone وفق واجهات Apple وقيودها الرسمية. يجب أن يعمل المنتج فعليًا، وأن يبين للمستخدم ما يمكن الوصول إليه وما لا يمكن نقله أو استعادته.

## سيناريوهات المنتج

1. **الهاتف إلى الكمبيوتر:** اكتشاف الهاتف، عرض أنواع البيانات والصلاحيات المتاحة، اختيار البيانات، نسخها إلى مجلد منظم والتحقق من سلامتها.
2. **الكمبيوتر إلى الهاتف:** اختيار ملفات أو نسخة احتياطية، تقييم توافق الاستعادة، وتنفيذها مع تقدم وأخطاء واضحة.
3. **هاتف إلى هاتف:** استخدام الكمبيوتر وسيطًا مع تقرير بالبيانات المنقولة وغير المتوافقة.
4. **النسخ الاحتياطي والاستعادة:** حفظ بيانات الجهاز المصدر وأنواع المحتوى وmanifest وهاشات السلامة، ثم استعراض النسخة واستعادة المتوافق منها.

## المنصات والبيانات

- Windows Desktop مركز التحكم: C# و.NET 8 وWPF وMVVM وClean Architecture.
- Android أولوية أولى، مع وكيل Kotlin عند الحاجة إلى صلاحيات/واجهات لا يوفرها ADB وحده. يطلب الوكيل أقل صلاحية لازمة وفي وقت استخدامها.
- iOS مجال بحث وتنفيذ مستقل، ولا يفترض التكافؤ مع Android أو الوصول إلى بيانات محمية.
- أولويات البيانات: الصور والفيديو والملفات والمستندات، ثم جهات الاتصال وسجلات المكالمات وSMS عند سماح النظام والصلاحيات. نقل التطبيقات وبياناتها الداخلية هدف استكشافي لا وعد عام.
- يصنف كل نوع بيانات إلى: نقل كامل، نقل جزئي، نسخ دون استعادة للنظام، أو غير متاح.

## الاتصال والأمان والاعتمادية

- ADB للاكتشاف والعمليات المصرح بها، وADB Reverse عند ملاءمته. المنفذ 4711 اقتراح أولي يحتاج مراجعة عند تصميم البروتوكول.
- النقل المجزأ وACK ومهلة أولية 30 ثانية وإعادة محاولة واستئناف حيث تسمح حالة الجلسة، مع تحقق من سلامة الملف.
- التصميم الأمني يستهدف ECDH وAES-GCM وSHA-256 ومصادقة الجهاز المقترن ومنع replay والتحقق من المدخلات ومسارات الملفات وعدم تسجيل الأسرار.
- لا يبدأ النقل قبل موافقة المستخدم. AES-GCM وحده لا يكفي لإثبات أمن القناة.
- يلزم التعامل مع انقطاع الاتصال وإلغاء المستخدم ونفاد التخزين والملفات الكبيرة والتكرارات والفشل الجزئي بتقرير صحيح.

## تجربة الاستخدام المستهدفة

يفتح المستخدم البرنامج، ويوصل الهاتف، فيتعرف عليه البرنامج ويوضح أنواع البيانات والأذونات المطلوبة. يختار المستخدم البيانات ويبدأ النقل ويتابع التقدم والسرعة والحجم المتبقي، ثم يستلم تقرير نجاح وفشل دقيقًا. لا تخفي الواجهة الأخطاء ولا تعرض نجاحًا صوريًا.

## ما أثبته مستودع GitHub عند تدقيق `v1.2.0`

المستودع العام عند `v1.2.0` أثبت وجود هيكل .NET/WPF وخدمات ADB وبعض نماذج التشفير ومحرك نقل أجزاء أولي. لم يثبت وقتها وجود دورة نسخ احتياطي/استعادة أو Android Agent أو iPhone أو وحدات بيانات حقيقية أو جلسة مقترنة موثقة. أضيف Android Agent وتعديلات محلية لاحقًا على فرع غير مرفوع؛ الحالة الحالية موثقة في `PROJECT_AUDIT.md` و`FEATURE_MATRIX.md`.
